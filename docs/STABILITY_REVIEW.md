# ASCEND — проверка памяти и стабильности

Дата: 14 ноября 2026.

Проверена активная сборка: SwiftUI/AppKit, пользовательские компоненты, настройки, формы, изображения, таймеры, наблюдатели, IPC-процесс Rust, SQLite, импорт и проверка данных. Исправления внесены в проект; приложение пересобрано в `dist/ASCEND.app`.

## Найденные проблемы и исправления

| Приоритет | Проблема | Исправление |
| --- | --- | --- |
| Высокий | Чтение и запись в pipe могли ждать бесконечно. Зависший движок удерживал незавершённые запросы и связанные объекты. Поиск перевода строки повторно сканировал весь накопленный ответ. | Отдельный `EngineProcess.swift`: неблокирующие FD, общий тайм-аут 30 секунд, проверка отмены не реже 100 мс, линейный поиск конца записи, ограничение ответа 128 МиБ, освобождение больших буферов и autorelease pool. Ошибки EOF, неверного JSON и превышения размера завершают повреждённый канал. Некорректные значения формы отклоняются до записи и не отключают исправный движок. |
| Высокий | Каждое изменение заметки ставило отдельный запрос в очередь. Каждый ответ включал весь профиль и аналитику. При медленном движке накапливались запросы и снимки состояния. | Один запрос в обработке. Промежуточные несохранённые изменения заметки объединяются с сохранением последнего текста и порядка пользовательских действий. Очередь ограничена; переполнение сообщает об ошибке. `busy` учитывает всю очередь. |
| Высокий | Каждый тик пересылал всю историю, аватар, журнал и заново рассчитывал аналитику. На паузе это тоже происходило каждую секунду. | Swift запрашивает компактный снимок только активной сессии. Полный ответ сохраняется для загрузки, изменений профиля и смены дня. Старые клиенты без `compact` продолжают получать прежний формат. Пауза опрашивается раз в 30 секунд, работающий таймер — раз в секунду. |
| Высокий | Рекурсивная проверка графа зависимостей могла переполнить стек на длинной цепочке. | Итеративный алгоритм с памятью O(V+E), без копирования всех списков зависимостей. Проверен на цепочке из 20 000 навыков со стеком потока 128 КиБ, включая обнаружение цикла. |
| Средний | Аватар заново декодировался при обновлениях нескольких экранов. Импортированное маленькое сжатое изображение могло иметь очень большие размеры после декодирования. | Общий кеш: до 8 записей, бюджет стоимости 8 МиБ, декодирование до 512 пикселей, проверка размера входа. Повторно используется один bitmap. Чтение и обработка выбранного изображения перенесены с главного потока. Оформление и обрезка аватара сохранены. |
| Средний | Отмена предварительного импорта скрывала диалог, но Rust продолжал держать импортированный профиль в памяти. | Добавлена отмена с освобождением кандидата. Новый импорт сначала освобождает старый. Отдельно проверена гонка между закрытием диалога и действием Replace: подтверждённый импорт не отменяется преждевременно. |
| Средний | Рекурсивная локальная функция последовательного удаления создавала риск удержания контекста и `Store`. Таймеры и мониторы очищались только при штатном завершении приложения. | Удаление использует метод со слабым захватом владельца. Добавлены идемпотентное завершение и очистка в `deinit`, слабая ссылка в AppDelegate, освобождение delegate/binding/callback у текстового поля. Монитор жеста ограничен своим окном и очищается при уничтожении координатора. |
| Средний | Закрытие приложения могло потерять последнее объединённое изменение заметки или оставить зависший дочерний процесс. | Перед выходом сохраняется последняя ожидающая заметка; ожидание ограничено двумя секундами. Затем закрываются FD, зависшему дочернему процессу отправляется завершение и при необходимости принудительная остановка. Главный поток не ждёт pipe синхронно. |
| Средний | Сохранение SQLite клонировало всю историю второй раз, чтобы затем очистить массивы метаданных. Загрузка сначала держала все JSON-строки, затем все декодированные объекты. | Метаданные сериализуются через заимствованные ссылки. Строки таблиц декодируются по одной. Транзакции, проверки и контроль revision сохранены. Заметка копирует только активную сессию; неудачный checkpoint откатывает изменение таймера в памяти. |
| Средний | Сборка перезаписывала исполняемый файл по месту, что опасно для уже запущенной копии с отображёнными страницами этого файла. | Исполняемые файлы устанавливаются через временные файлы и замену inode. |
| Оптимизация | Список навыков создавал все строки сразу. Форматтеры дат, таблицы перевода и порядок замен создавались повторно. | Ленивое создание строк с прежними параметрами расположения. Форматтеры и постоянные таблицы переиспользуются; пользовательские тексты не кешируются без ограничения. |

## Что проверено

- **39 тестов Rust**: core, storage, planner, bridge — все прошли.
- **Clippy с `-D warnings`**, `cargo fmt --check`, Swift со строгими предупреждениями — прошли.
- Реальный IPC smoke test: профиль, таймер, восстановление, начисления, JSON/CSV, аватар, старые профили, удаление навыков, пустой старт — прошёл.
- Нативные регрессионные тесты: зависшее чтение и запись, частичный/повреждённый/слишком большой ответ, EOF, отмена, нечисловые значения, 10 000 изменений заметки, порядок команд, подтверждение и отмена импорта, сохранение при выходе, освобождение Store, таймеров и наблюдателей, 10 000 обращений к кешу аватара — прошли. Проверки работают и в оптимизированной сборке (`precondition`).
- Системный **`leaks --atExit`** для нативных сценариев: **0 утечек, 0 потерянных байт**. Для диагностического тестового исполняемого файла разрешено чтение памяти; настройки подписи производственной `.app` не ослаблялись.
- Подпись `.app` проверена через `codesign --verify --deep --strict`.

Повторный запуск после сборки:

```sh
./scripts/cargo.sh test --locked -p ascend-core -p ascend-storage -p ascend-planner -p ascend-bridge
./native/tests/run-stability.sh
```

## Измерения

Отдельный искусственный профиль: 5000 сессий. Личные данные не использовались.

| Показатель | До | После |
| --- | ---: | ---: |
| Ответ фонового опроса без активной сессии | 8 082 193 байта | 36 байт |
| Медиана запроса в Python IPC-стенде, 20 опросов | 28,837 мс | 0,012 мс |
| RSS Rust-процесса в конце этого стенда | 46,7 МиБ | 38,5 МиБ |

Исправленный консольный Swift-клиент дополнительно выполнил 200 последовательных компактных тиков на том же объёме истории. Пиковый footprint процесса — около 51,5 МиБ. Исходный Swift-клиент не завершил этот сценарий за лимит 60 секунд; сравнительное уменьшение RAM Swift-клиента в процентах поэтому не заявляется. Это измерения транспортного стенда, а не FPS и потребление памяти всего графического приложения.

## Сохранение внешнего вида и ограничения проверки

Файлы оформления `Appearance.swift`, форм `Forms.swift` и assets совпадают с исходными по SHA-256. В `Screens.swift` единственное изменение — `VStack` → `LazyVStack` списка навыков с теми же отступами и параметрами. Изменения в окнах и настройках относятся к жизненному циклу, привязкам и кешированию. Цвета, размеры, отступы, анимации и обычные UI-тексты не менялись; добавлены только сообщения для ранее необработанных ошибок.

Результат `leaks` относится к перечисленным изолированным сценариям. Многодневное профилирование полного интерфейса в Instruments, включая внутренние GPU/SwiftUI-кеши системного Liquid Glass, не проводилось. Весь профиль по-прежнему загружается в память при открытии: его размер остаётся нижней границей потребления RAM. Исправления устраняют повторную передачу и ненужные копии, но не вводят пагинацию и не удаляют историю.
