# Strict mode — ASCEND 0.5.1

Включение: **Settings → General → Strict mode** / **Настройки → Основные → Строгий режим**. Настройка применяется сразу и сама по себе не включает камеру.

Перед каждой новой сессией появляется выбор **Use camera for this session**. Можно запустить сессию без камеры. Для строгой сессии нажмите **Enable camera**, разрешите доступ в системном диалоге macOS, сядьте перед камерой и дождитесь подтверждения присутствия. Лицо должно попадать в кадр; видимость плеч не требуется. Кнопка старта станет доступна после двух последовательных подходящих наблюдений.

После старта режим фиксируется до завершения сессии: включить камеру в обычной сессии или превратить строгую в обычную нельзя. Изменение общей настройки влияет на следующие сессии.

## Учёт времени

- При видимом лице в выбранной рабочей зоне таймер считает время. При исчезновении человека он ждёт возвращения; для возобновления нужны два свежих подходящих наблюдения.
- Проверяется один человек. Несколько лиц, неподходящая позиция, недостаточная уверенность распознавания или старые кадры не подтверждают присутствие.
- Ручная пауза выключает захват. Продолжение сохраняет выбранный строгий режим и рабочую зону; отсчёт ждёт нового подтверждения. Повторный запрос разрешения внутри активной сессии не показывается.
- При зависшей камере, отключении устройства или потере связи с движком время перестаёт начисляться. После сна дольше пяти секунд сессия встаёт на ручную паузу.
- После закрытия, сбоя или импорта активная сессия восстанавливается на паузе, с выключенной камерой. Время вне приложения не начисляется.
- Сохранить можно только время, подтверждённое таймером. Поле времени строгой сессии недоступно для редактирования; движок также отклоняет попытку увеличить его. Результат и отметка завершения квеста работают как прежде.
- Кнопка с крестиком в блоке строгой сессии сбрасывает её после подтверждения. Время, заметки и XP этой сессии не сохраняются. Это позволяет закрыть и сессию с нулевым временем.
- JSON и CSV сохраняют признак `strict` в истории. Старые профили и CSV без этого поля продолжают загружаться как обычные сессии. Настройка Strict mode хранится локально в настройках приложения.

## Камера, нагрузка и границы проверки

Захват через AVFoundation, распознавание через Apple Vision. Разрешение захвата — 640×480, если его поддерживает камера; анализ ограничен примерно двумя кадрами в секунду. Захват запускается и останавливается в отдельной последовательной очереди. Просроченные видеокадры отбрасываются. Для главного потока хранится максимум одно ожидающее наблюдение с координатами, без очереди изображений.

ASCEND не записывает видео, не захватывает звук, не отправляет кадры в сеть и не распознаёт личность. Предпросмотр показывается при подготовке; во время сессии остаётся компактный статус. Рабочая зона определяется по положению лица перед стартом. Это проверка присутствия лица в кадре, а не достоверная проверка позы сидя, внимания или выполнения работы. Фотография или другое изображение человека потенциально может обмануть такой детектор.

Swift отсеивает кадры старше одной секунды. Rust выдаёт краткое разрешение на начисление времени до 1,5 секунды от момента свежего наблюдения, вычитая задержку его доставки; каждое новое наблюдение обновляет его. Сигнал отсутствия отменяет разрешение. Движок начисляет только пересечение прошедшего времени с разрешённым интервалом, поэтому поздний Tick не добавляет время после истечения разрешения. Небольшая задержка остановки/возобновления возможна из-за частоты анализа, доставки кадров и округления до секунд.

При первом реальном запуске с камерой требуется разрешение macOS. Если доступ запрещён, приложение предлагает открыть настройки камеры либо начать без неё. Камера не включается при простом открытии настроек или окна подготовки.

## Проверка реализации

Автотесты покрывают отсутствие подтверждения, истечение разрешения, старые/будущие/чужие сигналы, паузу, сон, восстановление, ограничения сохранения времени, сброс без XP, JSON/CSV и старые данные. Swift-тесты проверяют реальный детектор Vision на публичном портрете и крупном плане без плеч, пустые кадры, два лица, геометрию, рабочую зону, пропавшие/повторные кадры и 1000 циклов подготовки/освобождения без включения камеры.

UI проверен на отдельном временном профиле. Физическая камера и системное разрешение в ходе разработки не включались. Точность распознавания и расход ресурсов при реальном захвате нужно проверить на конкретной камере и при обычном освещении пользователя.

Команды:

```sh
./scripts/cargo.sh test --workspace --locked
./scripts/cargo.sh clippy --workspace --all-targets --locked -- -D warnings
./native/tests/run-presence.sh
./native/tests/run-stability.sh
./native/tests/run-sessions.sh
./native/tests/run-quest-tree.sh
./native/tests/run-skill-tree.sh
./native/tests/run-notifications.sh
./scripts/build-app.sh
```

Документация Apple: [AVCaptureSession](https://developer.apple.com/documentation/avfoundation/avcapturesession), [разрешение на камеру](https://developer.apple.com/documentation/bundleresources/requesting-authorization-for-media-capture-on-macos), [детектор лица](https://developer.apple.com/documentation/vision/vndetectfacerectanglesrequest), [отбрасывание запоздавших кадров](https://developer.apple.com/documentation/avfoundation/avcapturevideodataoutput/alwaysdiscardslatevideoframes).
