# Проект: ASCEND — персональная система развития для macOS

ASCEND — локальное приложение на Rust, объединяющее RPG-прокачку персонажа, управление дисциплиной, развитие реальных навыков, планирование и анализ собственной эффективности.

Главная идея: ты управляешь персонажем, которым являешься сам. Его характеристики изменяются не от виртуальных действий, а от результатов в реальной жизни.

При этом приложение должно быть не обычным трекером привычек с XP, а системой, которая рассчитывает оптимальную нагрузку, отслеживает развитие навыков и помогает поддерживать долгосрочный прогресс.

## 1. Основные принципы

1. Реальные действия → развитие персонажа. Изучение Rust, завершение проекта, тренировки, регулярное питание и другие действия отражаются в системе.
2. Навыки важнее количества задач. Два часа осмысленной практики должны давать больше прогресса, чем десятки бессмысленных отметок.
3. Дисциплина измеряется стабильностью. Выполненные обещания себе важнее рекордной нагрузки за один день.
4. Баланс ограничивает бесконтрольную прокачку. Нельзя бесконечно фармить уровни одним простым действием. При этом специализация на одном важном навыке разрешена.
5. Восстановление — часть прогресса. Отдых учитывается при планировании нагрузки, но не превращается в источник бесконечных XP.
6. Пропуск не обнуляет достижения. Накопленные знания и уровни не исчезают из-за болезни или нескольких неудачных дней.
7. Все механики объяснимы. Пользователь видит, за что начислены очки, почему изменилась нагрузка и как рассчитываются показатели.
8. Приложение работает офлайн. Никаких обязательных аккаунтов, серверов, подписок и облачных зависимостей.

### Текущее состояние

В отличие от постоянных характеристик, эти параметры могут изменяться ежедневно:

- Энергия: субъективная оценка доступных сил.
- Утомление: накопленная нагрузка и потребность в восстановлении.

Приложение не должно изображать эти показатели как медицинские измерения. Они нужны для настройки персональной нагрузки.

## 3. Система навыков

Характеристики показывают общее развитие. Навыки — конкретные способности, которые можно тренировать.

Например, для технического развития:

Дерево навыков: Rust

Пример

Основы Rust

Типы, владение, заимствование

Асинхронность

Tokio, async/await

Архитектура

Модули, тестирование

Desktop-разработка

GUI, SQLite, macOS API

Завершённое приложение

Тесты, сборка, релиз

Каждый навык имеет собственный уровень, накопленный опыт, историю занятий и требования для перехода к следующему этапу.

Важно разделить опыт и мастерство. XP начисляются за практику, а значимые уровни мастерства открываются после подтверждения результата: решения задач, написания работающего кода, завершения проекта или успешной проверки знаний.

Таким образом, 100 часов просмотра уроков не приравниваются автоматически к 100 часам практического владения Rust.

## 4. Механика XP и уровней

Предлагаю использовать три независимых типа прогресса.

| Тип          | Назначение                     |
| ------------ | ------------------------------ |
| Skill XP     | Прокачка конкретного навыка    |
| Character XP | Общий уровень персонажа        |
| Mastery      | Подтверждённое освоение навыка |

### Расчёт опыта

Базовая формула:

\\[ XP = 10 \times \frac{t}{25} \times D \times R \\]

Где:

- \\(t\\) — подтверждённые минуты активной практики.
- \\(D\\) — коэффициент сложности от 0,8 до 1,2.
- \\(R\\) — коэффициент против повторного фарма.
- 10 XP — базовая награда за 25 минут практики средней сложности.

Время одной сессии, учитываемое при начислении опыта, ограничивается 125% первоначальной оценки. Дополнительную работу можно оформить как следующую сессию.

Примеры:

| Действие                                  | Результат                       |
| ----------------------------------------- | ------------------------------- |
| 25 минут изучения Rust, средняя сложность | 10 XP                           |
| 50 минут решения сложной задачи           | 22 XP                           |
| Завершение значимого этапа проекта        | +40 XP                          |
| Повторение простой привычки               | Небольшая фиксированная награда |

Бонусы за проекты фиксируются при планировании этапов, а не назначаются произвольно после выполнения.

Для повторяемых простых действий устанавливается предел наград за день. Настоящие продолжительные занятия не ограничиваются жёстким дневным потолком: после большого объёма однотипной работы лишь уменьшается скорость получения игрового XP.

### Прокачка уровня

Для следующего уровня требуется:

\\[ XP\_{\text{next}}(L)=100+40L \\]

Здесь \\(L\\) — текущий уровень, начиная с нуля.

Общий уровень персонажа повышается постепенно. Но сам по себе он не открывает сложные технические навыки: для них обязательно выполнение соответствующих условий мастерства.

Накопленный XP никогда не уменьшается. Если навык долго не практикуется, может снижаться отдельный показатель текущей подготовленности, но не исторический прогресс.

## 5. Дисциплина — отдельная система

Обычные streak-механики имеют недостаток: один пропущенный день уничтожает серию, даже если до этого человек успешно работал месяц.

Здесь нужна другая модель.

### Индекс дисциплины

Значение от 0 до 100, рассчитываемое по скользящему окну последних 28 дней.

\\[ D=100(0.7C+0.2S+0.1P) \\]

Где:

- \\(C\\) — доля выполненных заранее запланированных обязательств с учётом их приоритета.
- \\(S\\) — регулярность выполнения ежедневных ключевых действий.
- \\(P\\) — реалистичность оценки времени и объёма работы.

Все три показателя нормируются от 0 до 1.

Для защиты от накрутки задачи получают веса до начала выполнения. Выполнение десяти двухминутных дел не должно заменять невыполненную важную задачу.

Отдельно фиксируются дни отдыха, форс-мажоры и изменения планов. Они не превращаются в автоматические провалы.

### Правила дисциплины

- Начисляется за выполнение принятого плана, а не за максимальное число часов.
- Незапланированные полезные действия дают Skill XP, но не заменяют запланированные обязательства при подсчёте дисциплины.
- Если запланировано слишком много, система учитывает это при следующем планировании.
- При возвращении после перерыва нет штрафов на накопленный прогресс.
- Долгие серии можно показывать как статистику, но не привязывать к ним критические награды.

Приложение должно учить давать себе реалистичные обещания и выполнять их.

## 6. Главная механика — баланс

Это самый важный игровой модуль.

Нужно различать два вида баланса:

Баланс развития показывает, насколько равномерно достигаются выбранные цели.

Баланс нагрузки показывает, не превышает ли выбранный темп доступные ресурсы.

### 6.1. Баланс развития

Каждую неделю ты задаёшь приоритеты. Не все направления обязаны занимать одинаковое количество времени.

Например:

Недельный баланс

Пример целей и результатов

Изучение Rust

4/5 ч

Личный проект

2/4 ч

Физическая активность

2/3 занятия

Режим восстановления

4/5 дней

Сводное выполнение целей

# 69%

При равных весах

Формула:

\\[ B=100\frac{\sum_i w_i\min(a_i/t_i,1)}{\sum_iw_i} \\]

Где \\(t_i\\) — недельная цель, \\(a_i\\) — фактический результат, \\(w_i\\) — вес направления.

Для разных направлений можно использовать разные единицы: минуты, занятия или выполненные этапы. Направления без заданной цели исключаются из расчёта.

Главная особенность: перевыполнение одной цели не компенсирует невыполнение другой. Например, дополнительные часы программирования не закрывают цель по восстановлению.

При этом можно установить специализацию: 70% усилий на программирование и 30% на остальные задачи. Приложение не будет требовать искусственного равенства.

### 6.2. Баланс нагрузки

Каждое занятие имеет предполагаемую стоимость ресурсов:

- Умственная нагрузка.
- Физическая нагрузка.
- Временная стоимость.
- Необходимость восстановления.

На основании фактически выполненных занятий за предыдущие недели программа оценивает привычный объём работы.

Утром пользователь отмечает своё самочувствие и доступное время. Система сравнивает план с привычной нагрузкой и сообщает, когда он выглядит чрезмерным.

Например, если обычно выполняется 90 минут сосредоточенной работы, программа не должна внезапно предлагать шесть часов.

Она может предлагать увеличение нагрузки примерно на 10–15% после нескольких успешных недель. Это настраиваемое правило планирования, а не физиологическая норма.

Если отмечены сильная усталость, болезнь или плохое самочувствие, повышать нагрузку не нужно.

### 6.3. Адаптивная сложность

Раз в неделю система пересматривает рекомендации:

| Ситуация                                            | Реакция                                  |
| --------------------------------------------------- | ---------------------------------------- |
| Выполнение выше 80%, нагрузка комфортная две недели | Предложить небольшое повышение           |
| Выполнение 60–80%                                   | Сохранить текущую нагрузку               |
| Выполнение ниже 60%                                 | Предложить снизить или пересмотреть план |
| Усталость регулярно высокая                         | Приоритет восстановления                 |
| Один навык отстаёт                                  | Предложить перераспределение времени     |
| Приближается срок важного проекта                   | Временно переключить приоритеты          |

Автоматически повышать цели без согласия пользователя нельзя.

## 7. Квесты и реальные проекты

Нужно три вида заданий.

Главные квесты

Крупные цели с результатом и сроком: создать приложение, освоить технологию, завершить учебный проект. Они разбиваются на этапы, которые можно проверять.

Ежедневные задания

Конкретные шаги на сегодня: 50 минут Rust, одна задача по математике, завершение модуля программы.

Привычки и поддерживающие действия

Повторяющиеся действия: подготовка ко сну, поддержание порядка, перерывы, планирование следующего дня.

У квеста должны быть:

- Название, описание и проверяемый результат.
- Связанный навык, проект и приоритет.
- Оценка времени и сложности.
- Дедлайн, если он действительно существует.
- Условия завершения и награда.
- Возможность разбить его на подзадачи.
- История выполнения и переноса.

Статусы: `planned`, `active`, `paused`, `completed`, `cancelled`, `missed`.

Для крупных проектов нужен граф зависимостей. Например, пока не реализовано хранение данных, квест тестирования сохранения статистики остаётся заблокированным.

## 8. Ежедневный игровой цикл

### Утро — формирование плана

Приложение запрашивает минимум данных: самочувствие, доступное время и приоритет.

Затем предлагает не больше трёх основных обязательств. Мелкие необязательные задачи могут существовать отдельно.

План выбирается по алгоритму, который учитывает сроки, важность, отставание от недельных целей и предполагаемую нагрузку.

Это концептуальный макет, а не работающий таймер.

При запуске сессии:

1. Включается таймер, привязанный к конкретному навыку и заданию.
2. Можно ставить на паузу, добавлять короткие заметки и изменять состояние задачи.
3. После завершения фиксируются фактическое время и результат.
4. Движок рассчитывает XP, обновляет статистику и показывает объяснение награды.
5. Если достигнут этап проекта, проверяются условия разблокировки новых узлов дерева навыков.

Таймер необязателен: действия можно вносить вручную. Наличие запущенного таймера само по себе не доказывает выполнение задачи.

### Вечер — подведение итогов

Три коротких вопроса:

- Что удалось сделать?
- Что помешало выполнить остальное?
- Что стоит изменить завтра?

Система выводит заработанный опыт, завершённые этапы, выполнение плана и изменение состояния. Никаких штрафов за честно отмеченную усталость.

## 9. Антифарм и защита от неправильной мотивации

У игры должны быть ограничения, иначе пользователь начнёт оптимизировать количество XP вместо развития.

Основные механизмы:

1. Мелкие повторяемые действия имеют дневной предел наград.
2. Значимые бонусы привязаны к измеримым результатам.
3. Сложность и награды заранее фиксируются и не меняются после выполнения.
4. Цели не могут бесконечно дробиться для получения дополнительных бонусов.
5. Время практики учитывается отдельно от времени, потраченного на организацию задач.
6. Достижения не блокируют сон, отдых, питание и другие базовые потребности.
7. Система допускает перенос задач и пересмотр целей, сохраняя историю изменений.

Поскольку приложение персональное, тотальная проверка честности не нужна. Достаточно прозрачного журнала и корректно устроенных наград.

## 11. Аналитика

Приложение должно не только собирать информацию, но и помогать делать выводы.

Прогресс дисциплины

Пример за 8 недель

0/10025/10050/10075/100100/10012345678

Иллюстративные данные, не прогноз

Основные аналитические функции:

- Динамика дисциплины, концентрации и выполнения целей.
- Время, потраченное на каждый навык.
- Сопоставление запланированного и фактического времени.
- Распределение продуктивных сессий по дням и часам.
- Тренды субъективной усталости и нагрузки.
- История проектов, завершённых этапов и проверенных навыков.
- Прогноз достижения цели на основании текущего темпа, с указанием неопределённости.

Особенно полезен поиск закономерностей. Например: после каких типов занятий чаще возникают пропуски, насколько точны первоначальные оценки времени, какие цели регулярно откладываются.

Корреляции должны отображаться как наблюдения, а не как доказанные причинно-следственные связи.

## 12. Персонализация

При первом запуске пользователь выбирает направления развития, конкретные навыки, приоритеты и допустимое время.

Для твоего случая в качестве начальных направлений можно заложить:

| Направление          | Возможные цели                                           |
| -------------------- | -------------------------------------------------------- |
| Программирование     | Rust, разработка под macOS, системная архитектура        |
| Инженерия            | Математика, технические дисциплины, учебные проекты      |
| Самоорганизация      | Режим, планирование, выполнение обязательств             |
| Физическое состояние | Посильная регулярная активность, восстановление          |
| Питание              | Регулярность приёмов пищи без штрафов за вес или калории |
| Личные проекты       | От идеи до готового работающего продукта                 |

С учётом низкой текущей физической активности, эпизодов слабости и одышки приложение не должно автоматически предписывать интенсивные тренировки или поощрять преодоление выраженного недомогания. План физической активности нужно настраивать отдельно, а такие симптомы требуют медицинской оценки.

### Первоначальная калибровка

Первые семь дней система работает преимущественно в режиме наблюдения:

1. Фиксирует реальные действия.
2. Определяет примерную доступность времени.
3. Оценивает точность планирования.
4. Собирает первые данные о нагрузке и самочувствии.
5. Формирует стартовые рекомендации.

До накопления достаточной истории индекс дисциплины отображается как предварительный, а не как точная оценка.

## 14. Что не нужно включать в первую версию

Чтобы проект не превратился в незавершённую огромную систему, некоторые функции лучше отложить.

| Функция                                  | Решение                                        |
| ---------------------------------------- | ---------------------------------------------- |
| AI-коуч, анализирующий поведение         | После появления достаточной истории            |
| Синхронизация между устройствами         | Позже                                          |
| Интеграция с Apple Calendar              | Отдельный модуль                               |
| Автоматическое отслеживание приложений   | Необязательная функция с контролем приватности |
| Игровой магазин и косметические предметы | Только после проверки основных механик         |
| Сложная 3D-визуализация персонажа        | Не нужна                                       |
| Социальные рейтинги                      | Не нужны для персонального продукта            |

AI-коуч в будущем может анализировать историю, объяснять причины рекомендаций и предлагать изменения. Но вычисление XP, уровней и дисциплины должно оставаться детерминированным Rust-кодом, а не результатом генерации языковой модели.

## 15. Этапы реализации

Этап 1 — Игровое ядро

Характеристики, навыки, XP, задания, дисциплина, базовый баланс, SQLite, автоматические тесты. Это минимальный работающий продукт.

Этап 2 — Полноценное приложение macOS

GUI, Dashboard, таймер, дерево навыков, меню macOS, уведомления, сохранение сессий.

Этап 3 — Умное планирование

Аналитика, недельные обзоры, адаптивная нагрузка, рекомендации по перераспределению времени, долгосрочные цели.

Этап 4 — Стабилизация

Тесты сценариев пропуска дней, восстановление данных, резервное копирование, оптимизация производительности и упаковка в `.app`.

Каждую формулу нужно тестировать на крайних случаях: нулевое время, дублирование событий, массовое выполнение мелких задач, длительные перерывы, изменение целей задним числом. Систему баланса следует сначала проверять на симулированных историях, а уже затем использовать для рекомендаций.

## 16. Критерии успешного продукта

Приложение можно считать состоявшимся, если оно обеспечивает следующее:

- Ежедневное планирование занимает не больше нескольких минут.
- Пользователь может быстро начать и завершить занятие.
- Все изменения уровня и характеристик объяснимы.
- Нельзя получить большие награды простым многократным нажатием кнопок.
- Отставание от целей приводит к пересмотру стратегии, а не к наказанию.
- После продолжительного перерыва легко вернуться.
- Система позволяет отличать реальный рост мастерства от простого накопления часов.
- Личная информация не покидает компьютер без явного действия пользователя.

Итоговая концепция: ASCEND состоит из трёх взаимосвязанных движков — прокачки навыков, формирования дисциплины и управления балансом. Первый отвечает за развитие способностей, второй — за стабильность действий, третий — за реалистичность и устойчивость нагрузки. Именно их совместная работа должна отличать приложение от стандартного списка задач с игровой оболочкой.
